# 設計

## 構成

静的HTML/CSS/JavaScriptを配信し、問題編集と演習はブラウザだけで処理します。外部依存・ビルド工程はありません。ファイルを直接開けるよう、実行時のコードは通常のdeferスクリプトです。core/formatsはNodeからも読み込めます。

| 層 | 責務 |
| --- | --- |
| core.js | モデル、入力検証、ID、シャッフル、出題、採点、集計 |
| formats.js | バージョン付きJSON、既存CSV、任意階層manifestの変換 |
| storage.js | IndexedDBの原子的な書き込み、書き込みキュー、複数タブ競合検出 |
| app.js | 一覧、編集、プレビュー、インポート確認、演習、ダイアログ |
| samples.js | オリジナルの初期問題集。ユーザーデータとは独立 |

## データの寿命

問題集と問題は永続IDを持ちます。編集してもIDは維持し、複製時は新しいIDにします。選択肢のIDは並び順と分離し、シャッフルでも元の番号を表示します。解説中の番号がずれません。

演習開始時に対象問題のスナップショットを作成し、選択肢順・回答・入力途中の値・現在位置・スクロール位置を保存します。問題集の編集や削除に左右されず、その回は開始時点の問題で再開します。途中保存は1回、学習履歴は各問題の最新正誤と回数です。

保存はIndexedDB `quiz-studio-v1` の `state/workspace` に1つのスナップショットとして原子的に書き込みます。読み込み時のrevisionと保存先が異なれば、別タブからの更新として中止します。保存失敗を「保存済み」と表示せず、JSON書き出しによる救出を案内します。編集フォームの未保存入力は永続化せず、画面遷移・タブ終了時に確認します。

すべての状態を一度に保存する方式は初版の単純さを優先したものです。大量データ対応では問題集とセッションを別ストアに分け、変更単位で書き込む改修が必要です。上限付近の動作速度は未保証です。

## 拡張点

出題形式は `type` で分岐し、検証・採点はUIから分離しています。新しい形式を追加するときは、モデル/検証、採点、CSV/JSONアダプター、編集画面、表示画面、テストを一組で追加します。互換性を破る変更はschemaVersionを上げて移行関数を用意します。

画像を扱う場合はファイル添付用ストアと持ち運び形式を設計し、外部URLの自動読み込みや任意HTML実行を導入しない方針です。

## 静的で可能なこと／サーバーが必要なこと

| 静的サイトで実装済み | 将来別途サーバーが必要 |
| --- | --- |
| 問題編集、分類、ローカル保存 | ログイン、端末間自動同期 |
| CSV/JSONの読み書き | 複数人での同時編集 |
| 採点、履歴、途中再開 | 中央集約した学習分析 |
| オリジナル例題のデモ | 公開問題集の投稿・審査・検索 |

GitHub Pagesには `web/` の静的ファイルだけを置きます。閲覧者が作った問題や回答はリポジトリに追加されません。同じオリジンでホストする他のアプリからのストレージ分離はブラウザのオリジン単位なので、専用のホスト名が望ましい構成です。
